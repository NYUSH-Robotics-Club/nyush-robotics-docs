# 02 Engineering Notebook Official Requirements

## Chapter Goal

Convert official notebook guidance into execution-level team standards.

## 1. Official Definition

`EN1` defines notebook as student-originated, chronological evidence of engineering process, not a last-minute polished artifact.

Implication:

- continuous logging is expected
- failures and iteration should be visible
- post-hoc storytelling is risky

## 2. Format: Physical or Digital

Official guidance allows both:

- physical notebook
- digital notebook

Both are judged with the same rubric expectations.

## 3. Core Content Expectations

At minimum, weekly entries should include:

- goals and constraints
- candidate options and tradeoff rationale
- test method and raw results
- failures and fixes
- next iteration plan

This aligns with `EN6` process evidence emphasis.

## 4. Academic Honesty and Citation

`EN3` requires proper source attribution for external content.

Recommended practice:

- keep one references appendix
- annotate source link and usage purpose

## 5. AI/LLM Boundary

`EN4` explicitly warns that using AI/LLM to generate/rewrite core notebook content conflicts with student-centered intent and conduct expectations.

Practical policy:

- language polishing is acceptable with caution
- engineering decisions and process records must remain student-authored and explainable

## 6. Judge Workflow Context

Official judge workflow commonly includes:

- classify notebooks as Developing vs Fully Developed
- apply rubric scoring and comparative ranking
- evaluate under limited time windows

So clarity and structure matter as much as total page count.

## 7. Weekly Template (Actionable)

Use one primary entry per week with:

- weekly objective
- design changes
- measured test data
- decision rationale
- failure and fix
- next-week plan

## 8. Chapter Tasks

- Task A: self-audit notebook against EN1/EN3/EN6
- Task B: backfill last two weeks with failure/fix evidence
- Task C: add source appendix and citations
