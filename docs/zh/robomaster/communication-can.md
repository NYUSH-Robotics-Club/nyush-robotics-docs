# 通信与 CAN

## 你需要先明确三件事

1. 当前系统是单板还是双板。
2. 哪些设备挂 CAN1，哪些挂 CAN2。
3. 谁发控制帧，谁收反馈帧，ID 是否冲突。

## CAN 工程要点

- 同一总线严禁重复 ID。
- 终端电阻只在总线两端开启。
- 电机控制频率与反馈频率要和总线带宽匹配。

## 板间通信：CANComm 模块

双板场景下，`CANComm` 提供结构化收发封装。

关键点：

- 发送和接收数据结构长度由 `sizeof()` 指定
- 默认单帧用户数据上限 `60` bytes
- 通信用结构体必须 `#pragma pack(1)`，避免 padding 导致解析错误

## Message Center 与 CANComm 的分工

- 板内应用间：优先 `message_center`（pub-sub）
- 板间：`CANComm`

建议把“应用逻辑”与“跨板运输”分开，避免模块耦合。

## 高频故障与定位优先级

1. 硬件与接线（CAN_H/CAN_L，电源与地）
2. 过滤器和 ID 映射
3. 结构体长度与 pack
4. 任务频率与总线负载
5. 中断优先级与回调逻辑
